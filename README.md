# Factor Lab — оркестратор и факторный анализ изменения ЭКпрбк

Часть 3 общей задачи. Сервис сам собирает данные из двух других частей и объясняет, почему
изменился экономический капитал под процентный риск (ЭКпрбк) и NPV портфеля:

```text
источник сделок ──► Factor Lab ──► curve-parser (часть 2): кривая MOEX на дату + 6 шоков IRRBB
   (CSV/HTTP)           │      ──► cashflow-rs (часть 1): потоки, PV, NPV по 7 кривым
                        │
                        ├─ ЭКпрбк = min ΔNPV по стресс-сценариям на каждую отчётную дату
                        ├─ точное разложение изменения по Шепли (пересчёт калькулятором)
                        ├─ факторная модель: нелинейность, взаимодействия, устойчивость
                        └─ LLM (Codex SDK) объясняет только посчитанные факты, числа сверяются
```

## Архитектура

```text
backend/src/factor_lab/
  domain/            кривые и смешение участков, ролл-форвард сделок, метрики ЭКпрбк, точный Шепли
  application/       use cases и порты
    ports.py         DealSource, CurveService, Calculator, RunRepository, Explainer
    pipeline.py      оркестрация прогона
    decomposition.py разложение изменения метрики между датами
    analytics/       универсальная факторная модель (схема, профиль, модель, формы, взаимодействия)
    facts.py         факты с id и путём к источнику для LLM
    verification.py  проверка чисел в тексте LLM
    explanation.py   LLM-слой с запасным детерминированным объяснителем
  adapters/          cashflow-rs HTTP, curve-parser HTTP, источник сделок, PostgreSQL, LLM (codex, template)
  api/               FastAPI
  container.py       композиционный корень
```

Зависимости направлены внутрь: `domain` не знает ни HTTP, ни БД; `application` знает только порты;
конкретные реализации собираются в `container.py`. Заменить LLM — значит реализовать `Explainer`
и указать его в контейнере, метод анализа не меняется.

## Метод

1. **Данные.** Сделки забираются из `DEALS_SOURCE` (файл или HTTP-URL в формате `deals.csv`).
   Для каждой отчётной даты сделки сдвигаются по контрактному графику калькулятора: остаток —
   после последнего платежа до даты, погашенные выбывают.
2. **Кривые.** На каждую дату у curve-parser берётся кривая последнего торгового дня (при
   отсутствии — запускается загрузка с MOEX) вместе с шестью шоками IRRBB.
3. **ЭКпрбк.** NPV по базовой и шести стресс-кривым → ΔNPV по сценариям → минимум.
4. **Точное разложение.** Изменение ЭКпрбк и NPV между датами раскладывается на четыре группы:
   течение времени и амортизация, короткий (≤1 г.), средний (1–5 л.) и длинный (>5 л.) участки
   кривой. Для всех 16 коалиций калькулятор пересчитывает портфель; для смешанных кривых шоки
   строит curve-parser (`POST /api/v1/curves/shock`). Вклады Шепли в сумме равны изменению
   метрики; парные индексы взаимодействия показывают совместное действие. Базовый метод для
   сравнения — изолированные эффекты по одному фактору: их несходимость с изменением — мера
   нелинейности (минимум по сценариям, выпуклость) и взаимодействий.
5. **Факторная модель** на панели «сделка × дата» без жёсткого списка факторов: все колонки
   сделки и форма кривой классифицируются автоматически (число, дата → годы до даты наблюдения,
   категория; константы, ключи, колонки с пропусками отбрасываются с причиной). Дальше —
   профилирование, линейная модель против градиентного бустинга на кросс-валидации по сделкам,
   permutation-важность, формы partial dependence (порог, насыщение, U-образность), H-статистика
   Фридмана для пар, условный эффект «A при низком/высоком B», локальные вклады Шепли для
   отдельных наблюдений, устойчивость рангов между фолдами, гиперпараметрами и половинами периода.
6. **Надёжность.** Мало данных, слабая модель или неустойчивое ранжирование дают вердикт
   `insufficient`/`unreliable`/`unstable`, который попадает в факты и в текст LLM.
7. **LLM.** Получает только факты с id, отвечает JSON по схеме, обязана цитировать `[F#]`.
   `verification.py` извлекает каждое число из текста и ищет его среди фактов; несовпадения
   показываются в интерфейсе.

## HTTP API

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/v1/health` | состояние БД, калькулятора, кривых, LLM |
| GET | `/api/v1/deals?dataset=` | портфель из источника или синтетический |
| POST | `/api/v1/datasets` | сгенерировать синтетический портфель `{name, params}` → 202 |
| GET | `/api/v1/datasets` | синтетические портфели; `/{id}`, `/{id}/download`, `DELETE /{id}` |
| GET | `/api/v1/generator/defaults` | параметры генератора по умолчанию |
| GET | `/api/v1/prepayment` | ставки CPR калькулятора |
| GET | `/api/v1/targets` | целевые метрики факторной модели |
| POST | `/api/v1/runs` | запуск прогона `{start, end, frequency, target, explain, dataset, prepayment, prepayment_rates}` → 202 |
| GET | `/api/v1/runs` | история |
| GET | `/api/v1/runs/{id}` | статус, прогресс, результат, объяснения |
| POST | `/api/v1/runs/{id}/explanations` | объяснение или ответ на вопрос `{question}` |
| GET | `/api/v1/runs/{id}/export.csv` | отчёт |

## Генератор синтетических сделок

`factor_lab/application/generator.py` строит портфель по распределениям: остаточные сроки
(интервалы с долями), типы погашения (`ANN`, `RGM`, `SIMPLE`), фиксированная или плавающая
ставка (CBKEY1M + спред), периодичность платежей, суммы (лог-равномерно), диапазоны ставок,
доля субсидируемых кредитов и спред субсидии, доли моделей досрочного погашения, валюта.
Доли нормируются, неизвестные значения и неверные интервалы отклоняются с пояснением. Сделки
проходят валидацию калькулятора; одинаковые параметры и seed дают тот же файл при любом числе
процессов. Портфель строится в фоне и выбирается в прогоне полем `dataset`.

## Запуск и тесты

Весь стенд поднимается из корня рабочей папки общим `docker-compose.yml`. Локально:

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
PYTHONPATH=src .venv/bin/uvicorn factor_lab.api.app:app --port 8000
```

Тесты на синтетике проверяют, что метод находит заложенный порог, насыщение и взаимодействие,
отличает шумовой признак, сообщает о нехватке данных; сквозной тест прогоняет оркестрацию на
фейковых портах и проверяет, что вклады Шепли сходятся с изменением ЭКпрбк и NPV.

## Ограничения

- Портфель двигается без новых выдач; досрочные погашения — постоянный CPR по модели сделки,
  одинаковый во всех сценариях.
- Глобальная важность и формы — оценки суррогатной модели, а не калькулятора.
- `data/indicators.csv` дополняет историю ключевой ставки решениями Банка России до 27.10.2025;
  для более поздних дат используется последнее известное значение.
